# Glossary

## 작성 규칙

- 프로젝트에서 하나의 의미에는 하나의 대표 용어를 사용합니다.
- 코드 표현은 실제 class, field, API와 Database 명명에 사용할 영문을 기록합니다.
- 약어는 전체 이름과 함께 정의합니다.
- 같은 의미로 사용하지 않을 표현을 명시합니다.

## 용어

| 용어      | 영문·코드 표현 | 정의      | 사용하지 않을 표현       | 관련 개념 |
| --------- | -------------- | --------- | ------------------------ | --------- |
| 작성 필요 | `작성 필요`    | 작성 필요 | 해당 없음 또는 작성 필요 | 작성 필요 |

## 외부 용어

외부 시스템이나 업계 표준의 의미를 프로젝트에서 그대로 사용하는 경우 출처와 차이를 기록합니다.

| 용어      | 출처      | 프로젝트에서의 의미 | 차이 또는 주의점 |
| --------- | --------- | ------------------- | ---------------- |
| 작성 필요 | 작성 필요 | 작성 필요           | 작성 필요        |

## 완료 기준

- Requirement, Business Rule, Screen, Domain, API와 Database에서 같은 개념을 같은 용어로 표현합니다.
- 정의가 서로 순환하지 않습니다.
- 구현자가 추가 해석 없이 코드 이름을 정할 수 있습니다.
