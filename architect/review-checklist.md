# 검토 체크리스트

- Owner: Architect
- Purpose: 문서와 아키텍처 변경의 검토 기준을 제공합니다.
- Audience: 모든 역할
- Dependencies: `governance.md`, `feature-lifecycle.md`

## 체크리스트

- [ ] 미해결 `{{...}}` 플레이스홀더가 의도치 않게 남아 있지 않습니다.
- [ ] 특정 이전 프로젝트의 이름, 도메인과 기술이 남아 있지 않습니다.
- [ ] 모든 개념에 단일 소유자와 source of truth가 있습니다.
- [ ] 공유 개념을 역할별 문서에서 중복 정의하지 않습니다.
- [ ] 요구사항에 사용자 가치, 범위와 acceptance criteria가 있습니다.
- [ ] 비즈니스 규칙이 검증 가능한 형태입니다.
- [ ] 용어집, 도메인 모델과 API 계약이 같은 용어를 사용합니다.
- [ ] 시스템 경계와 의존성 방향이 명확합니다.
- [ ] 데이터 저장을 사용하면 table, column, key, constraint와 index가 정의되어 있습니다.
- [ ] 데이터 생명주기, 개인정보, migration과 복구 전략이 정의되어 있습니다.
- [ ] 데이터베이스 schema 정의와 실행 가능한 migration이 일치합니다.
- [ ] API 요청, 응답, 오류와 인증 요구사항이 명확합니다.
- [ ] 중요한 tradeoff가 decision log 또는 ADR에 기록되어 있습니다.
- [ ] README와 문서 간 상대 링크가 유효합니다.
- [ ] 구현과 문서가 일치합니다.
- [ ] 관련 테스트와 검증 방법이 정의되어 있습니다.
