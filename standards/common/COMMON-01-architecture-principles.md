# Architecture Principles

## 기준

- **STD-COMMON-010** 제품 의미와 비즈니스 규칙은 구현 기술, 저장 방식과 UI 표현으로부터 독립적으로 정의합니다.
- **STD-COMMON-011** 하나의 개념, 상태와 데이터에는 정확히 하나의 소유 컴포넌트와 source of truth를 둡니다.
- **STD-COMMON-012** 컴포넌트 경계는 기술 계층보다 변경 이유와 책임을 기준으로 나눕니다.
- **STD-COMMON-013** 공유 계약은 소비자가 내부 구현이나 persistence model을 알지 않아도 사용할 수 있어야 합니다.
- **STD-COMMON-014** 외부 시스템과 framework는 교체와 테스트가 가능한 명시적 경계 뒤에 둡니다.
- **STD-COMMON-015** 중복 저장이나 파생 상태가 필요하면 갱신 책임, 정합성 조건과 복구 방법을 정의합니다.
- **STD-COMMON-016** 장기적인 선택의 이유, 검토한 대안과 영향은 해당 Requirement의 관련 설계 구역에 기록합니다.
- **STD-COMMON-017** 구현 구조가 문서화된 경계와 달라지면 코드를 기준으로 묵인하지 않고 설계 또는 구현을 정렬합니다.
