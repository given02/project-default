# Update 7.1.0

## 버전

- 출발 버전: `7.0.0`
- 대상 버전: `7.1.0`

## 주요 변경

- Architect와 Developer를 서로 다른 Codex 컨텍스트로 분리합니다.
- Architect 주 컨텍스트는 최신 고성능 모델로 명세, `Ready`와 `Done` 승인을 담당합니다.
- Backend와 Frontend Developer Agent는 `gpt-5.6-terra`, reasoning `medium`으로 범위가 확정된 구현과 테스트를 담당합니다.
- Developer가 production code를 변경하기 전에 Requirement를 `In Progress`로 전환하고 실행 소유권을 기록하게 합니다.
- 다른 Agent는 `In Progress` Requirement를 수정할 수 없으며 쓰기 Agent는 순차 실행합니다.
- Developer가 `Review`로 전환하면 기존 Architect 컨텍스트가 직접 검토하고, 다음 역할이 남으면 다시 `Ready`, 모두 끝나면 `Done`으로 전환합니다.

## 호환성

기존 Requirement 구조와 역할 권한을 유지하면서 컨텍스트 분리, 모델 기본값과 실행 소유권을 추가하는 호환 가능한 MINOR update입니다.

3. Developer는 production code를 수정하기 전에 Requirement를 In Progress로 전환하고 다음 실행 소유권을 기록하게 하세요.

   - 활성 Agent
   - 시작 시각

5. 다른 Agent는 Requirement가 In Progress이면 실행 소유권의 범위와 관계없이 같은 Requirement의 모든 파일을 변경하지 않게 하세요.
6. Developer는 구현과 검증이 끝나면 완료 시각과 실제 결과를 기록하고 Review로 전환한 뒤 종료하게 하세요.
7. Backend와 Frontend가 모두 필요하면 첫 역할의 Review 후 Architect가 검토하고 다음 역할을 지정해 Ready로 전환한 다음 순차 실행하게 하세요.
8. 모든 필요한 구현 역할이 완료되고 Architect 검토가 끝난 뒤에만 Done으로 승인하게 하세요.
9. 구현 재작업만 필요하면 Architect가 담당 역할과 범위를 지정해 Ready로 전환하고, 명세 결정이 필요하면 Blocked를 해결한 뒤 Ready로 승인하게 하세요.
