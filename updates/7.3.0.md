# Update 7.3.0

## 버전

- 출발 버전: `7.2.0`
- 대상 버전: `7.3.0`

## 주요 변경

- Backend package를 business domain 우선으로 구성합니다.
- 각 domain 내부에서 `api`, `application`, `domain`, `infrastructure` 책임을 구분합니다.
- Application service는 구체적인 adapter가 아니라 기술 독립적인 port를 사용합니다.
- JPA, QueryDSL과 persistence entity는 Infrastructure 내부 구현으로 제한합니다.
- Infrastructure는 기본적으로 평평하게 유지하고 실제 책임이 늘어날 때만 하위 package로 분리합니다.
- 공통 base package 예시는 `com.jhome.core`와 `CoreApplication`을 사용합니다.

## 호환성

기존 기능의 의미를 변경하지 않고 새 Backend package 구조 Standard를 추가하는 MINOR update입니다. 기존 프로젝트의 production code를 이 update에서 자동 이동하지 않으며, 이후 생성하거나 명시적으로 재구성하는 코드에 새 규칙을 적용합니다.

[Backend Package Structure Standard]

standards/backend/BE-08-package-structure-convention.md를 만들고 STD-BE-080부터 STD-BE-089까지의 고유 규칙으로 다음을 정의하세요.

1. Backend package는 application 전체를 기술 계층으로 먼저 나누지 않고 Requirement의 business domain을 먼저 나눕니다.
2. 각 domain 내부를 api, application, domain, infrastructure 책임으로 구성합니다.
3. Spring Boot 진입점은 모든 domain의 공통 상위 base package에 둡니다. 예시는 com.jhome.core.CoreApplication 아래에 user와 order를 둡니다.
4. 독립 배포되는 단일 domain service에서 base package가 이미 domain을 나타내면 domain package를 중복 생성하지 않고 빈 package도 만들지 않습니다.
5. api에는 Controller, 외부 request·response model, 형식 검증과 protocol 변환을 두며 repository, persistence model과 business rule을 직접 사용하지 않습니다.
6. application에는 use case service, command·query·result, transaction boundary와 port를 두고 domain 동작과 port 호출 순서를 조정합니다.
7. Application service는 구체적인 adapter, Spring Data repository, QueryDSL과 persistence entity 대신 application port에 의존합니다.
8. domain에는 entity, aggregate, value object, policy, event와 domain failure를 두고 Spring MVC, Spring Data, JPA, QueryDSL, HTTP와 database vendor 타입에 의존하지 않습니다.
9. infrastructure에는 port adapter, persistence entity, framework repository, external client와 messaging 구현을 두고 JPA와 QueryDSL은 adapter 내부 구현으로 사용합니다.
10. Port는 기술 독립 타입으로 계약을 표현하고 framework paging, query와 persistence 타입을 노출하지 않습니다. Aggregate 저장·조회는 repository port가 소유하고 복잡한 읽기가 독립적으로 필요할 때만 query port를 분리합니다.
11. Infrastructure는 기본적으로 평평하게 유지하고 persistence, cache, client 또는 messaging처럼 서로 다른 책임이 실제로 늘어날 때만 책임 기준 하위 package로 나눕니다. JPA, QueryDSL 또는 PostgreSQL 사용만으로 기술별 package를 만들지 않습니다.
12. 설명 예시에는 com.jhome.core.CoreApplication과 user domain을 사용하고 UserRepositoryPort, UserQueryPort, UserJpaEntity, UserJpaRepository, UserRepositoryAdapter와 UserQueryAdapter의 관계를 보여주세요.
13. UserRepositoryAdapter는 UserRepositoryPort를 구현하고 UserJpaRepository를 내부에서 사용하며, UserQueryAdapter는 복잡한 조회가 있을 때만 UserQueryPort를 구현하고 QueryDSL을 내부에서 사용한다고 설명하세요.
14. 단순하고 한 adapter에서만 사용하는 변환은 private 변환으로 시작하고 복잡하거나 재사용될 때만 persistence mapper를 분리한다고 설명하세요.
